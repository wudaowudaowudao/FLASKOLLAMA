# 引言  

为深入推动中国中车进一步深化科技体制改革，推进科技创新与产业创新的深度融合，按照大创新体系进一步优化协同创新生态，提升创新效率与产品竞争力，构建轨道交通装备和清洁能源装备“双赛道双集群”适用的研发数字化体系，推动产品研发实现双赛道产业兼容、多维度体系融合、分层式研发递进、全生命周期贯通、穿透式精准管理、数智化高效赋能。  

依据大创新体系建设总体思路、中车产品研发管理总体要求和研发数智化转型的“1个研发生态、1套体系标准、N个案例应用、4个企业能力建设”的总体目标，形成一套研发数字化体系标准规范。通过构建指南系统性指导研发数字化建设工作，通过流程规范统筹全集团研发流程，通过数据架构设计规范和应用架构设计规范统筹数据架构和信息系统架构建设，通过研发指标与成熟度评价推进研发数字化体系的建设与持续改进。  

Q/CRRC丁278《研发数字化体系》拟由6部分组成：  

-—第1部分：构建指南。目的在于描述研发数字化体系的总体框架，给出业务架构、数据架构、应用架构的设计要点，提出体系运行评价和体系支撑保障建设要点。  
一—第2部分：流程规范。目的在于规定研发数字化体系中研发流程的定义和划分原则，明确研发流程的管理内容和管控要求、输入和输出要求。-—第3部分：数据架构设计规范。目的在于规定研发数字化体系中数据架构的组成及管理原则，明确研究数据资源目录、数据标准、数据模型和数据分布的设计方法。  
—第4部分：应用架构设计规范。目的在于规定研发数字化体系中应用架构的组成及管理原则，明确应用架构设计方法。  
一—第5部分：研发指标。目的在于规定研发域指标框架，明确研发投入、研发过程、研发效果等维度的指标定义规则。  
一—第6部分：成熟度评价规范。目的在于规定研发数字化体系成熟度评价模型，明确成熟度等级和关键过程评价要素。

# 5研发流程内容  

# 5.1 业务流程  

# 5.1.1 技术及技术平台规划  

# 5.1.1.1制定技术及技术平台规划计划  

根据国家、集团、公司的发展战略和科研规划，综合技术需求急迫度、资源满足度等因素，确定技术及技术平台研究内容及优先级的过程。  

# 5.1.1.2 制定技术及技术平台规划方案  

编制规划文件，明确规划目标，开展现状评估与需求分析，确定技术策略，制定具体技术规划内容的过程。规划方案应包括技术研发的阶段、时间表、资源分配表等。  

# 5.1.1.3 管理技术及技术平台规划与评估  

对技术及技术平台规划的实施过程进行管控、调整的过程。应建立监督和评估机制，定期检查规划实

施情况，评估技术转化应用效果，根据评估结果和环境变化，及时调整技术规划。  

# 5.1.2产品平台规划  

# 5.1.2.1 制定产品平台规划计划  

依据公司科技发展规划及研发需求输入，通过收集市场需求和研发需求信息，识别产品平台研发需求，制定产品平台规划工作方案及计划，明确任务和时间节点，并完成评审的过程。  

# 5.1.2.2制定产品平台规划方案  

依据产品平台规划计划，开展产品平台规划，编制产品平台规划书，通过分析产品平台需求现状，确定产品平台顶层参数、技术指标、发展路线和开发计划等过程。  

# 5.1.2.3管理产品平台规划与评估  

对产品平台规划的实施过程进行管控、调整的过程。应建立监控和评估机制，定期检查规划实施情况，评估平台产品市场表现，根据评估结果和环境变化，及时调整规划。  

# 5.1.3 技术研究  

# 5.1.3.1 设定技术目标  

拓宽技术来源，开展需求调研，获取相关前沿技术信息，分析发展趋势，确定技术方向，形成技术概念和应用设想，完成技术目标设定。  

# 5.1.3.2 制定研究方案  

根据技术目标和需求，开展技术研究，形成研究方案，评估方案的可行性和风险。  

# 5.1.3.3 技术功能验证  

识别技术研究过程中的分析、试验等技术验证项点，制定技术研究及验证计划（含验证项目、资源）。运用仿真等手段对关键功能/特性进行验证。  

# 5.1.3.4 技术发布  

根据技术验证结果，评估技术成熟度，制定技术应用说明，确定发布方式并进行技术发布，推广应用成果。  

# 5.1.4技术平台开发  

# 5.1.4.1技术平台开发可行性分析  

基于市场调研，对现有技术成熟度、资源配置、面临风险等进行整体分析评估，形成可行性分析报告的过程。  

# 5.1.4.2技术平台开发策划  

明确技术平台的研究目标，制定资源分配计划，制定技术平台研究计划，提出项目团队成员组成的相关建议、要求的过程。

# 5.1.4.4 技术平台验证  

通过单元测试、集成测试、系统测试、用户现场测试等，对单元模块、系统集成、技术平台进行功能性验证，记录测试结果和问题，优化平台功能的过程。

# 5.1.5产品平台开发  

# 5.1.5.1产品平台开发可行性分析  

分析技术可行性、技术难点，评估资源需求及风险的过程。  

# 5.1.5.2产品平台设计策划  

依据产品平台立项申请及产品平台规划书，对产品平台的设计过程进行策划的过程。本阶段应编制产品平台建设任务书，明确产品平台顶层参数、技术指标、关键配置、设计任务及目标要求。依据任务书中目标和要求，分解产品平台需求，制定产品平台开发计划，明确各项工作内容、完成时间和责任人。  

# 5.1.5.3产品平台方案设计  

依据产品平台建设任务书、产品平台需求分解及产品平台开发计划，确定产品平台总功能、系统功能、技术选型、软硬件接口的过程。  

# 5.1.5.4产品平台技术设计  

依据产品平台方案，确定总体设计布局、主要系统和关键零部件选型以及确定各系统或部件间接口的过程。  

# 5.1.5.5产品平台施工设计  

依据产品平台技术方案进行产品平台详细设计的过程，本阶段应完成产品平台技术文件、图样、物料清单（BOM）等设计及评审。  

# 5.1.5.6产品平台试制验证及确认  

采用仿真、试制、试验等方式对产品平台的技术符合性进行验证和确认的过程。  

# 5.1.5.7产品平台定型发布  

获得行业型号许可（如：型号合格证、CRCC证书）或通过RAMS考核期或通过线路型式试验/运用考核/试运行等、发布并归档产品平台设计文档的过程。

# 5.1.6.1产品设计策划  

任务分配、实现载体明确和各项设计控制活动的策划过程，通过需求分解制定开发计划，明确工作内

# 5.1.6.2产品方案设计  

将用户需求转化为产品的工业设计方案和/或总体方案，为用户提供可选择的产品维形，同时应考虑全寿命周期维保需求。本流程主要工作内容为：开展设计分析和历史同类产品源头设计质量问题分析，提出应对措施，确定实现设计开发所需的技术方案。  

# 5.1.6.3 产品技术设计  

总体设计布局、主要系统和关键零部件选型以及确定各系统或部件间接口的阶段，通过对产品的系统或部件进行详细描述，及/或通过制作模型进行展示，向用户提供一个更详细的产品定义。  

# 5.1.6.4产品施工设计  

完成产品制造所需的全部设计文件的过程。主要工作内容为：绘（编）制完成产品图样、图样目录（需要时）、施工设计文件和 BOM。  

# 5.1.6.5产品试制验证及确认  

将工作图样转化为实物的过程，并通过一定的验证方法（如检查和试验），评估实物产品的技术符合性和安全性。  

# 5.1.7检修维护开发  

# 5.1.7.1 检修设计策划  

根据产品定期检修合同和用户需求等相关要求、委外修清单以及检修标准制定相关的文件资料，开展检修设计策划，提出检修设计指标，提出评审要求及设计输出文件等。  

# 5.1.7.2 检修方案设计  

涵盖检修技术设计，开展检修工艺方案的设计、评审及制定检修工艺设计计划，在对顾客要求、法律法规、技术标准、设计图样、制造技术条件、试验大纲等技术文件分析的基础上，进行检修产品工艺方案策划，主要包含工艺布局、工艺要点、检验要点、工艺技术准备项目、工艺试验策划、工艺及检验流程图等，同时需将质量问题以及项目差异项的应对措施纳入产品工艺方案。  

# 5.1.7.3 检修施工设计  

检修施工设计是完成产品检修所需的全部工艺规程文件和检修质量控制文件并确定检修工艺装备的过程，本阶段为检修工艺设计的实施阶段，主要工作为开展差异项及规程分析、工艺规程、检验文件、工艺结构及B0M、工装任务书、技术条件、技术协议、过程失效模式及影响分析、技术定额及维修制造配置基线的准备等工作。  

# 5.1.7.4 试修鉴定  

针对首次定期检修产品，在试修完成后进行产品试修鉴定。鉴定前应进行试修总结，其内容应包括但不限于：试修产品性质、试修时间和数量、关键问题及解决过程、检修规程验证情况、检修工艺文件和检修装备验证情况、检修质量控制情况、试修结论等。  

# 5.1.8产品服役阶段设计  

# 5.1.8.1 修程优化  

在产品进入服役期后，根据产品可靠性寿命评估、检修成本、产品运用及定期检修中出现的问题等，提出检修优化建议，制定优化方案，完成运用考核和评估，最终完成对检修规程的修订。  

# 5.1.8.2 报废处置  

产品寿命终结时，根据产品设计信息提出拆解及各部件报废方法，编写报废处置方案。  

# 5.2 管理流程  

# 5.2.1 研发需求管理  

# 5.2.1.1 研发需求收集  

承接市场、科技规划等方面需求输入，通过文档分析等结构化方法，从技术规划书、平台研发规划书、招标规格书等输入中获取显性需求，通过场景分析挖掘用户潜在隐性需求的过程，并同步识别法规限制、技术可行性等约束条件，需求评审确认完整性。  

# 5.2.1.2 研发需求整理和分析  

将需求转化为研发过程输入的过程，通过系统化地收集、分类、优先级排序和可行性评估，并通过评审、澄清等方式逐项对需求进行确定，确保需求准确性和可实现性。  

# 5.2.1.3 研发需求分解与分配  

将需求转化为清晰、可执行的研发任务的过程，并分配给相关团队或人员，实现需求落地的责任清晰化和执行具体化。  

# 5.2.1.4 研发需求实现  

将经过整理、分析、分解和分配的需求，通过设计、开发等环节，最终转化为可交付的产品或功能的过程。  

# 5.2.1.5 研发需求验证和确认  

在需求实现后，通过系统化的方法确认需求的准确性和完整性，并验证需求是否被正确实现的过程。验证由开发团队主导，通过静态分析、动态测试等方法检查需求是否被正确实现；确认需客户参与，通过验收测试等评估需求是否满足真实需求。  

# 5.2.2研发项目管理  

# 5.2.2.1 研发立项管理  

在新项目开始之前，对项目进行全面规划、评估和决策的过程。涉及确定项目的目标、范围、资源需求、时间计划、风险评估等方面，以确保项目能够成功实施并达到预期目标。  

# 5.2.2.2 研发计划管理  

根据研发项目目标，系统确定研发项目的任务，安排任务进度，确定所需资源预算的过程。应按照研  

Q/CRRCJ278.2—2025  

发计划，从进度、质量、成本等方面推进，以确保项目在合理时间内实现低成本、高质量的研发。  

# 5.2.2.3 项目实施监控  

在研发项目执行过程中，通过系统化方法对项目进度、成本、质量、风险等关键指标进行跟踪、评估和控制的过程。应建立监控机制，定期收集项目数据，评估关键指标，及时发现问题并处置，确保项目按计划推进。  

# 5.2.2.4结题与后评价管理  

在研发项目达到预定目标并完成任务后，对项目的执行过程、效益作用和影响等方面进行全面总结、评估、验收和后续管理。通过结题与后评价管理分析项目效益和影响，提出改进措施，为后续项目提供参考。  

# 5.2.3研发质量管理  

# 5.2.3.1 变更管理  

对产品全生命周期中设计输出载体的变更进行控制和管理，以确保变更带来的风险得到充分识别、评估和控制，同时实现变更带来的预期效益的管理过程。  

应根据变更输入开展变更影响分析，并进行变更策划，变更内容评审通过后通过改图通知等形式下达正式变更，由执行部门完成变更内容后，进行变更的验证和确认工作。  

# 5.2.3.2 设计评审管理  

对研发过程中的设计评审活动进行计划、组织、控制和监督的过程。设计评审应确保被评审对象（技术方案、结构、计算、试验、样机等）的适宜性、充分性、有效性，以确保设计达到设定目标。  

设计评审活动包含但不限于：技术可行性评审、设计输入评审、设计策划评审、方案设计评审、技术设计评审及施工设计评审、设计变更评审等。  

# 5.2.3.3技术风险评估管理  

在研发活动中，识别潜在风险、评估风险的影响程度，并制定技术风险应对策略的持续过程。  

# 5.2.3.4 老化管理  

在规定的或协定的产品生命周期内，对老化风险进行有效管理和控制的一系列措施。老化管理应涵盖设计、开发、采购、生产和运用过程的必不可少的管理活动，确保由合同规定或定义的产品和备件生命周期内（含质保期限）的可用性。  

# 5.2.3.5 RAMS管理  

对产品或系统的可靠性、可用性、可维护性和安全性进行的综合管理和优化。通过一系列措施和流程来确保产品或系统的可靠性、可用性、可维护性和安全性达到预定的标准和要求。  

RAMS 工作覆盖项目招投标、设计开发，到产品服役的全过程，并包含供方产品 RAMS 管理等方面的工作内容。  

应包含FMEA的管理工作，用于确定产品或过程中潜在的失效模式，评估这些失效模式对系统的影响，并制定相应的预防和纠正措施。  

# 5.2.4构型管理  

# 5.2.4.1 构型管理计划  

确定产品型号研制各阶段应开展的构型管理工作及各阶段对应的构型要求和目标，在初期阶段形成构型管理计划，构型管理计划应明确组织和职责。构型管理整体计划包括构型标识策划、构型控制过程策划、构型纪实策划、构型审核策划等内容。  

# 5.2.4.2 构型标识  

对构型项进行确定，并对构型项进行定义，实现数据文件化、基线化(形成设计基线、制造基线、维修基线)等。并通过唯一标识对构型及其状态进行明确标识。  

# 5.2.4.3 构型控制  

构型控制核心目的是要保障构型项相关基线能得以保持或在允许变化的范围内的保持。其核心手段包括构型的更改控制等。  

# 5.2.4.4 构型纪实  

构型纪实目的是通过记录构型项及构型控制过程中相关信息及构型文件，为构型管理过程提供可追溯性，包括：更改验证纪实、更改过程纪实、更改发放纪实等。  

# 5.2.4.5 构型审核  

功能审核是由管理人员评价配置项的功能特性和物理特性是否被精准地用文件定义，并符合已批准的产品需求的要求，物理审核是由管理人员评价首批(件)生产的配置项实物是否符合其配置文件的规定。  

# 5.2.5 研发碳管理  

# 5.2.5.1 碳目标制定  

需要根据国家双碳目标要求和集团/企业发展战略，基于企业实际情况和行业先进水平，结合自身的生产规模、技术水平、资金实力等因素，制定明确的长期碳减排目标，如明确不同时间点的减碳量，明确实现碳中和的时间。同时，将长期目标分解为若干短期目标，便于分步实施和跟踪考核。  

# 5.2.5.2 碳排放核查  

对企业生产经营过程中的各类碳排放源进行详细梳理和量化，包括能源消耗（如煤炭、电力、天然气等）、工业生产过程（如研发、设计、生产、制造、试验及生产辅助等全流程）、交通运输（如原材料运输、产品配送）等各环节产生的二氧化碳及其他温室气体排放。  

# 5.2.5.3 碳路径制定  

需要分析排放结构与重点源，明确不同生产制造过程、不同排放源在总排放量中的占比，找出降低碳排放的重点环节和关键设备，制定针对性减排措施，如通过能源管理优化（提高能源利用效率、优化能源结构、建立能源管理系统等）、生产过程改进（采用低碳工艺和技术、加强废弃物管理与循环利用等）、供应链管理（绿色采购、优化物流配送等），并明确具体的减碳指标。  

# 5.2.5.4 碳绩效管理  

Q/CRRCJ278.2—2025  

针对减碳目标和路径建立碳排放监测体系，定期开展评估与审计，包括碳减排量、能源利用效率、经济效益、市场反馈等方面。对比实际绩效与目标绩效，分析偏差原因，根据绩效评估结果和市场需求变化，持续投入资源对已有的双碳技术和产品进行优化和升级。关注行业技术创新动态，及时引入新的理念、方法和技术。  

# 5.3支撑流程  

# 5.3.1 研发数据资产管理  

# 5.3.1.1 技术文件管理  

对产品全生命周期过程中各类技术文件进行类型定义、标准化创建、存储、版本控制、共享、归档和销毁等过程。  

# 5.3.1.2 BOM管理  

对产品全生命周期管理过程中各类BOM（如设计BOM、仿真BOM、试验BOM）进行结构化定义、分类定义、版本控制、关系跟踪及生命周期管理等过程。  

# 5.3.1.3 设计模型管理  

对各类设计模型（如概念模型、逻辑模型、物理模型、机器学习模型、数据流模型等）进行系统化创建、类型定义、标准化管理、共享权限设置等过程。  

# 5.3.1.4仿真试验数据管理  

对产品仿真试验过程中产生和传递的数据（几何模型、网格模型、载荷工况、边界条件、脚本、计算结果、仿真报告等）进行创建、收集、整理、分析、存储、传播和利用的过程。  

# 5.3.2研发知识与成果管理  

# 5.3.2.1 技术情报管理  

通过系统化方法对技术相关信息进行管理的过程。企业应对技术情报进行收集、整理、分析、存储和利用，为企业的决策、创新、知识资产增值及竞争力提升提供支持。  

# 5.3.2.2 知识产权管理  

对知识、知识创造过程和知识的应用进行规划和管理的活动。企业应建立贯穿研发活动全流程的知识产权合规管理体系，对研发活动中产出的创新成果进行系统化、规范化和战略性的知识产权开发、保护、运用和管理。  

# 5.3.2.3 技术标准管理  

对技术标准的制定、实施、监督和更新等环节进行管控的一系列活动。各标准起草单位依据标准项目计划开展后续制定工作；标准发布后，各标准归口单位组织标准相关单位进行贯彻实施；经过一段时间的实施应用，标准归口单位组织监督检查，并根据反馈意见进行修订更新或废止，最终完成技术标准的闭环管理。  

# 5.3.2.4技术秘密管理  

Q/CRRCJ278.2—2025  

针对不为公众所知悉、具有商业价值且采取合理保密措施的技术信息进行的管理活动。企业应建立技术秘密认定和保密管理机制，对研发过程中产出的具有保密价值、具备保密条件且专利公开后难以维权的技术创新成果进行保护。  

# 5.3.2.5其他研发知识与成果管理知识管理  

企业还应对其他研发知识和成果进行有效管理，建立相应的制度和流程并组织落实。  

# 5.3.3研发共用基础管理  

# 5.3.3.1 研发物料管理  

对所需物料的申请、使用和跟踪等环节进行系统化管理的过程。该流程确保研发过程中物料的申请、合理使用和有效控制，支持研发项目的顺利进行。  

# 5.3.3.2 模块化管理  

对产品模块进行划分、标识、设计、签审、应用、变更、维护及模块库的构建、管理等活动。模块化需综合考虑产品研发、制造、运维等不同场景的需求，并在产品构成的系统、部件和零组件等不同层级开展，实现模块接口与安装方式的标准化和系列化。  

# 5.3.3.3 通用件管理  

通用件是指在不同类型或同类不同规格的产品中可以互换使用，并进行统一编号管理的零部件。通用件管理应包括通用件的分类、标识、签审、变更、维护以及通用件库的构建、管理等内容。  

# 5.3.3.4标准件管理  

标准件是指由各级标准化部门审批颁发的并具有标准编号的零部件。标准件管理应以优选及简统化为导向，包括标准件的分类、标识、应用审查以及标准件库的构建、管理等内容。  

# 5.3.4研发资源管理  

# 5.3.4.1 研发软件管理  

对用于支持研发过程的应用软件或系统的管理过程。主要包括对研发软件的分类分级、登记与标记、适用与维护、更新、移动和报废等管理内容和要求。  

# 5.3.4.2 研发硬件管理  

对研发相关设备的日常使用、保养维护、设备新购与移交、设备升级、设备报废管理等过程。主要包括对试验检测装置、办公设备、计量器具、工具工装等的管理。  

# 5.3.4.3 研发人力管理  

针对研发团队成员所进行的一系列人力资源管理活动。主要包括对研发团队角色定义、岗位能力及职能分工的管理。  

# 5.3.4.4对外合作管理  

企业与外部单位就技术开发、转让、许可、咨询或者服务进行相关合作的管理过程，一般需要建立技

# 5.3.4.5 供应商协同研发管理  

企业与供应商在研发阶段建立协作关系，通过整合技术、资源等方式完成产品开发的管理模式。主要包括外购件设计管控的职责分工、管控内容、保密要求、供方评价等工作。  

# 5.3.4.6研发经费管理  

对企业研发活动资金进行规划、分配、使用监督及效果评估的系统化管控过程。主要包括预算编制、资金分配、成本控制、合规管理等工作。

# 1 工作简况  

# 1.1 编制依据  

根据“关于印发《中国中车2025年技术标准项目计划》的通知”（中车集团办科信（2025）95号）“2025CRRC009基于数智转型的研发数字化体系 第2部分：流程规范”的要求，由中车科技质量与信息化部归口，并由中车青岛四方机车车辆股份有限公司、中国中车股份有限公司、中车唐山机车车辆有限公司、中车长江运输设备集团有限公司、中车株洲电力机车研究所有限公司、中车大连机车车辆有限公司、中车齐齐哈尔车辆有限公司共同起草。  

本文件为首次制定。  

# 1.2制修订本标准的必要性  

为深入贯彻中车数智化转型整体战略，培育和发展数智转型的新质生产力，以研发数字化为核心支撑轨道交通装备和清洁能源装备技术创新以立新优势，系统性推进研发数智化工作。在归口单位建立的《研发数字化体系建设专项方案》指导下，通过对国内外研发数字化体系现状充分研究，形成《研发数字化体系》系列标准制定工作任务，本文件为系列标准第2部分《研发数字化体系流程规范》。  

# 1.3 编制过程  

在本文件的编制过程中，完成了大量的基础研究和编写工作，并邀请了国内和铁路行业相关领域的专家进行了技术审查，确保了标准的规范性和权威性。本文件编制过程概要如下：  

（1）标准计划下达后，在归口单位指导下，中车青岛四方机车车辆股份有限公司、中国中车股份有限公司、中车唐山机车车辆有限公司、中车长江运输设备集团有限公司、中车株洲电力机车研究所有限公司、中车大连机车车辆有限公司、中车齐齐哈尔车辆有限公司等单位成立了标准起草组，对研发研发体系核心构成要素等情况进行了调研，收集了相关技术资料，初步形成了工作大纲和本文件的草案稿。  

（2）通过专项研讨方式，归口单位组织多轮次的草案稿研讨，研讨参与单位除起草组外包含中车株洲电力机车研究所有限公司、中车长春轨道客车股份有限公司、中车南京浦镇车辆有限公司、中车工业研究院有限公司、中车大同电力机车有限公司、中车信息技术有限公司、中车重庆智慧轨道交通技术有限公司、中车启航新能源技术有限公司、中车戚墅堰机车有限公司等。  

（3）标准起草组对前期工作和标准草案深入讨论研究后，于2025年6月形成了本文件的征求意见稿并发送株洲所，由株洲所审查后上报中车科技质量与信息化部，征求意见稿发往中车各一级子公司进行意见征集。  

（4）征求意见过程中，共收到21个单位反馈的共98条意见，标准起草组对中车各一级子公司的反馈意见进行了深入讨论研究及修订，2025年7月形成了本文件的送审稿并发送株洲所。

# 2 编制原则  

2.1标准格式统一、规范，符合GB/T1.1—2020要求。  

2.2标准内容符合统一性、协调性、适用性、一致性、规范性要求。  

2.3标准内容具有系统性、科学性、指导性。  

2.4 标准实施后有利于系统性指导集团、子企业的研发数字化建设工作，符合集团研发管理总体发展需求。

# 4 关键指标的确定  

4.1课题由集团科信部统筹指导，四方股份牵头，参研单位覆盖集团内轨道交通装备、清洁能源装备整机及核心部件企业，共计15 家。课题内各单位参研人员专业覆盖研发设计、体系管理、数据治理、信息技术等多个方面。基于集团数智转型工作考虑，流程架构需明确表达出技术、平台、产品之间的逻辑关系，覆盖研发全过程业务，兼顾质量管理体系、构型管理体系、碳 $^+$ 研发体系，并适配集团轨道交通及清洁能源业务。4.2 首先根据集团管理规范，将目前全部的业务活动进行梳理完整；其次要在体系的要求下，完成业务逻辑的整理和闭环；第三，借鉴IPD设计理念及工作经验，完成流程的层级整理；最后，数据治理是数智转型的重要内容，要通过数据治理的方法将整理完成的业务流程进行数字结构化转换。  

4.3主流分类方法包含：  

1）OES 分类：Operation-业务流程，Enable-使能流程，Support-支撑流程，以客户为中心，以项目交付为主的企业，为更好的理解企业的流程；对应集团内轨道交通装备业务;2）POS 分类：Plan-战略流程，Operation-业务流程，Support-支撑流程，稳定性、周期性和计划性行业；对应集团清洁能源装备业务；结合集团业务特点，综合OES 和POS分类方法，将流程分为业务类、管理类和支撑类。  

4.4主流分层方法包含：  

1）生命周期法：围绕核心管理对象的生命周期全过程来规划流程；如针对研发业务从规划至产品服役全生命周期过程，形成技术规划、技术研究、平台开发、产品开发、产品检修服役等L2过程，针对L2 层级产品开发，又根据其生命周期特点，拆分为设计策划、方案设计等L3流程；2）PDCA法：当业务具有明显的计划-实施-检查-处理的特点；如项目管理拆分至立项、计划、实施、后评价等L3层级；3）分类树法：根据业务的功能、场景等进行穷举分类展开；如支撑类流程拆分至研发知识、共用基础、研发资源等L2层级。在流程分类的基础上，保证流程完整性，综合采用生命周期法、PDCA法、分类树法，划分出L2/L3层级。
